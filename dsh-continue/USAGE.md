# 使用 dsh-continue

一句话：**打开之后，这条会话只要停下来，就自动补发一条「继续」。**

---

## 1. 开启

在输入框敲（这是斜杠命令，不会作为 prompt 发给模型）：

```
/continue 1
```

回一张卡：

```
自动续跑：已开启
会话停下来 500ms 后自动发送「继续」。
上限：不限
关闭：/continue off
```

之后每次这一轮跑完，插件会等 500ms、复查 agent 真的空闲、inbox 没排队，
然后替你发一条内容为 `继续` 的消息。它会一轮接一轮自己跑下去。

## 2. 关闭

```
/continue 0
```

随时可用，哪怕 agent 正在跑。

## 3. 全部写法

| 输入 | 行为 |
| --- | --- |
| `/continue 1` | 开启，**不限**轮数 |
| `/continue on` | 同上 |
| `/continue 开` / `开启` | 同上 |
| `/continue 0` | 关闭 |
| `/continue off` | 同上 |
| `/continue 关` / `关闭` / `停` | 同上 |
| `/continue 5` | 开启，**本次最多补发 5 次**，到点自动关 |
| `/continue on 5` | 同上 |
| `/continue` | 查状态 |
| `/continue status` / `/continue 状态` | 同上 |

> `1` 是「开」，不是「1 轮」。要限轮数就写 `2` 以上，或 `/continue on N`。

---

## 4. 会自动帮你踩刹车的情况

不用担心它无脑循环。下面这些情况它自己会停：

| 情况 | 行为 |
| --- | --- |
| 你点了「停止」按钮 | **立刻自动关闭**，会话里留一张可见的关闭说明 |
| 连续 2 轮以错误结束 | 自动关闭 |
| 撞上不可恢复的错误（额度用完、认证失败、上下文超限…） | 立刻自动关闭 |
| 到了你设的轮数上限 | 自动关闭 |
| inbox 里还有排队的输入 / agent 其实还在跑 | 这一轮不动手 |
| 这一轮跑完后你插了话 | 不动手 |
| 被父级或宿主中止（不是你按的停止） | 这一轮不续，但**保持开启** |

自动关闭时你会看到这样一张卡（**不花模型那一轮**）：

```
自动续跑已关闭：用户手动停止了这一轮。已自动补发 7 次「继续」。
```

## 5. 想换补发的内容

默认发 `继续`。想改成别的，改 profile 的 `cordis.patch.yml`
（`~/.dsh/profiles/desktop/cordis.patch.yml`），加这一段：

```yaml
- id: dsh-continue
  config:
    text: "接着做，别停"
```

重启宿主生效。同一段里还能调：

| 键 | 默认 | 说明 |
| --- | --- | --- |
| `text` | `"继续"` | 发什么 |
| `delayMs` | `500` | 停下来之后等多久才发 |
| `maxRounds` | `0` | 补发上限，`0` = 不限 |
| `maxConsecutiveErrors` | `2` | 连续几轮出错后自动关闭 |
| `continueOnError` | `true` | 单轮出错后是否也续跑 |
| `stopOnUserAbort` | `true` | 你按停止时是否自动关闭 |
| `enabled` | `true` | 设 `false` 等于卸载 |

## 6. 典型用法

**让 agent 把一个大任务做完**

```
把 docs/ 下所有 Markdown 里的死链找出来并修掉，逐条改。
/continue on
```

它会自己一轮一轮往下推，直到任务真的收尾（然后前端那轮没有工具调用了，
它还是会继续发 —— 所以你盯着点，做完就 `/continue off`）。

**限个预算**

```
/continue 8
```

最多补发 8 次，到点自动关，适合睡前挂机。

**只在长输出被截断时续写**

不用开自动续跑。这种情况下 agent 的 `turn/end` 是 `max-tokens`，
直接 `/continue 1`，写完一段它会自动接着写下一段，直到写完；
写完发现还在发就 `/continue 0`。

---

## 7. 注意

- **状态存在内存里。** 重启 DeepSeek Harness 就清空，需要重新 `/continue on`。
  这是刻意的：没人希望重启之后一条几周前的会话突然自己开始烧 token。
- **只对当前进程里活着的会话生效。** 从历史里新打开一条会话，要重新开一次。
- **等审批的时候不会触发。** 工具卡在权限弹窗、`ask_user_question` 等你回答时，
  agent 还在 `running`，这时候该说话的是你，它不会插嘴。
- **它会替你说「继续」。** 这条消息在历史里就是一条 user 消息，和你手敲的一样。
